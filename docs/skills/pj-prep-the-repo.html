pj-prep-the-repo

Prepares a new or an existing repo for the pj skills. Run it once. It is safe to run again.

InputNone. Works on the current repo.
RequiresA GitHub remote. gh is logged in.
ResultLabels and the attachments branch exist. A PR adds AGENTS.md, CLAUDE.md, and .pj/config.json.

Procedure

The procedure is SKILL.md. This page does not repeat it. In short, prep:

  • Stops before any change if the default branch is not main, git is older than 2.42, or the clone is shallow.
  • Creates the labels and the orphan attachments branch, and offers the pj-main and pj-attachments rulesets.
  • Opens one PR with AGENTS.md, CLAUDE.md, .pj/config.json, and the enforcement configs that the user accepts.
  • Runs its git and gh work through tested scripts in scripts/. A rerun after a crash is safe.

In Claude Code, the pj plugin also installs a guard hook. It blocks the forbidden actions of the Autonomy rules in repos that have .pj/config.json.

Config

.pj/config.json holds the settings of the skills for this repo.

{
  "biteSize": "medium",
  "timezone": "UTC"
}

timezone is an IANA name, for example Europe/Berlin. The devlog and the reports use it. The default is UTC.

biteSizeMax acceptance criteriaMax diff lines
small7400
medium8800
large91600

pj-implement and pj-decompose read it. If the file is missing, use medium.

Attachments branch

The attachments branch holds evidence. It is an orphan branch: it has no code and no history in common with main.

WhereWhatWhy
attachmentsSpecs, mockups, screenshots, test output, before/after capturesHistory at a point in time. It stays readable if GitHub is lost.
main, docs/Data model, diagrams, ADRsThe current state of the system only. pj-implement updates them in each PR.

Layout:

attachments
├── devlog/yyyy-mm-dd/hhmmss-<skill>-<id>.html   one file per entry
├── issues/<n>/spec.md        snapshot at spec-ready
├── issues/<n>/design.md      from pj-implement
├── issues/<n>/mockups/…
├── issues/<n>/evidence/…
└── prs/<n>/evidence/…     PRs with no issue

Links:

https://github.com/<o>/<r>/blob/attachments/issues/<n>/…?raw=true

Rules:

  • Write with scripts/attach.sh. It writes from a temporary detached worktree, so the main checkout never switches branches.
  • If a push fails, the script fetches, rebases, and pushes again, up to 10 times. Each run writes to its own paths, so a rebase conflict means a real clash. The script then stops.
  • Keep files small: png or webp. Do not add video.
  • Link by branch path, not by commit SHA. Links then survive a squash of the branch.
  • The branch has no workflow files, so CI does not run on it.
  • To find cleanup actions, run pj-healthcheck.

AGENTS.md

AGENTS.md says what good looks like. The skills say how the workflow runs. All agents follow AGENTS.md, with or without the pj skills.

The pj rules live between markers. A new run replaces the text between the markers and keeps all other text.

# AGENTS.md

## Project
Stack: … | Build: … | Test: … | Lint: …

…
