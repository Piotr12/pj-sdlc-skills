pj-healthcheck

Checks the repo setup, the attachments branch, and the docs/ folder. Suggests actions. It does not change anything.

InputOptional: setup, attachments, or docs to run one part only. Default: all.
RequiresNone. A repo that was not prepared fails the setup checks.
ResultA report in the session, with the commands for each suggested action.

Setup checks

CheckFindingSuggested action
ToolsA tool from the tools list is missing: gh or its login, git 2.42 or later, a headless browser, a stack tool, an enforcement tool.The install command from the tools list.
Labelsneeds-input or spec-ready is missing. An issue has both labels.Run pj-prep-the-repo. Remove the wrong label.
Attachments branchThe branch is missing, or it shares history with main.Run pj-prep-the-repo. Recreate the branch as an orphan.
AGENTS.mdThe file or the pj rules block is missing, or the block differs from the current pj rules.Run pj-prep-the-repo.
Config.pj/config.json is missing or has a value that is not valid.Run pj-prep-the-repo.
Worktrees.worktrees/ is not in .gitignore. A worktree for a merged or closed PR. A review- worktree that a run left behind, or a stale entry in git worktree list.Run pj-prep-the-repo. git worktree remove <path>, git worktree prune.
CLAUDE.mdThe file does not import @AGENTS.md.Run pj-prep-the-repo.

Attachments checks

CheckFindingSuggested action
OrphansA folder for an issue or PR that does not exist.Delete the folder.
Unpicked variantsA mockup variant on a closed issue that the spec does not name as the pick.Delete the variant.
Rule breaksVideo, a file over 1 MB, an image that is not png or webp, a path outside the layout.Delete, compress, or move the file.
ConsistencyAn issue with spec-ready and no spec.md.Run pj-grill-for-specs-readiness again.
History sizeThe branch history is much larger than its current files.Squash the branch.

Docs checks

Compare docs/ with the source code on main. The code is the truth.

CheckFinding
Data modelAn entity or relation in the code that is not in docs/data-model.md, or the opposite.
StatesA state or transition in the code that is not in the stateDiagram, or the opposite.
ADRsCode that contradicts an ADR that is not superseded.
API contractAn endpoint or field in the code that is not in the contract, or the opposite.
ReferencesA link or path in docs/ to a file or symbol that does not exist.
AGENTS.mdA command in the Project section that does not exist in the repo.
Rule breaksAn erDiagram with more than 9 entities. Mermaid that does not parse.

For each finding, give the doc location, the code location, and the correction. Mark each finding as certain or possible.

Keep

Never suggest to delete these. They are the history of the system.

  • spec.md and design.md.
  • The mockup variant that the spec names as the pick.
  • All attachments of open issues and open PRs.

Rules

  • Read-only. The human runs the commands, and decides which docs findings get an issue.
  • A delete breaks the links to that file in issue comments. Tell the user which issues have such links.
  • A delete does not make the repo smaller. Only a squash of the branch does. Say this in the report.
  • A squash keeps the paths, so links still work. It needs a force-push to attachments, and only a human does that.

Devlog

At the end of the run, append one entry to the devlog. Also append one if the run stops early.
