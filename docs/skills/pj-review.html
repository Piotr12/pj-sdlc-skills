pj-review

Reviews a PR adversarially. Works for PRs from agents and from humans.

Input#pr
RequiresAn open PR.
ResultOne review on GitHub, with inline comments and a verdict. A human approves and merges.

Steps

  1. Find the round number: count the earlier pj-review reviews on the PR. If the round limit is reached, stop.
  2. Collect the input: the diff, the linked issue, spec.md, design.md, docs/, and AGENTS.md.
  3. Check out the PR head in a detached worktree .worktrees/review-<pr>. Install the dependencies. Remove the worktree at the end.
  4. Run build, lint, and tests. Use the commands from the Project section of AGENTS.md.
  5. Review in a subagent with a fresh context. Use a different model if one is available.
  6. Verify each finding in a second pass. Try to prove that the finding is wrong. Drop each finding that does not hold.
  7. Post one review with inline comments and the verdict.

Rubric

  1. Correctness. The code meets each acceptance criterion and each edge case. No bugs.
  2. Spec. Each deviation from the spec is recorded under Agent decisions.
  3. Tests. Each acceptance criterion has a test. Each test fails when the behaviour breaks. Each surviving mutant has a reason.
  4. Risks. Security, access, and performance match the spec.
  5. Docs. docs/ shows the new state: data model, states, ADRs.
  6. Rules. The code follows AGENTS.md.
  7. Simplicity. No complexity that the spec does not need. No dead code.
  8. UI. The screenshots match the picked mockup. Accessibility rules are met. Source of ideas: Vercel web-design-guidelines.

Findings

  • Each finding is blocking or non-blocking.
  • Each finding gives the location, the reason, and a fix.
  • Start each comment with [pj-review]. The GitHub account is the same as the author, so this tag tells the threads apart.
  • A failing build, lint, or test is blocking.

Review body

pj-review round 2/3

Verdict: 1 blocking, 3 non-blocking
Build ✓  Lint ✓  Tests ✗ (1 failing)
Size: 1 140 lines, larger than expected (bite size medium: 800)

Round 1 findings: 4 fixed, 1 declined with reason

Rounds

  • Maximum 3 rounds for each PR.
  • From round 2: check that the earlier findings are fixed, and review the diff since the last round.
  • Resolve each of your own threads when you verify the fix. Do not resolve threads from humans.
  • Do not raise a non-blocking finding again if pj-address-review declined it with a reason.
  • After round 3, list the open findings for the human and stop.

Rules

  • Post the review as a comment, not as approve or request changes. A human approves. GitHub also blocks an approval of your own PR.
  • If the diff is larger than the bite size limit, say so in the review body. It is not a finding.
  • PR with no issue: use the PR description in place of the spec. Report that there is no spec as non-blocking.
  • Save evidence, if any, to attachments. Use issues/<n>/evidence/, or prs/<n>/evidence/ if the PR has no issue.

Related

Devlog

At the end of the run, append one entry to the devlog. Also append one if the run stops early.
