pj-next-round

Looks at the issues, PRs, and repo, and suggests the next actions. It does not change anything.

InputNone. Works on the current repo.
RequiresNone.
ResultThe top 5 actions as commands to paste, and the actions for the human.

Steps

  1. Read the open issues, their labels, and their linked PRs.
  2. Read the open PRs: review rounds, unresolved threads, CI status.
  3. Find the possible actions with the table below.
  4. Sort them by priority. Pick the top 5.
  5. Group the actions that can run in parallel.
  6. Show the report. Write the commands in the syntax of the current agent, ready to paste.

Actions

PriorityStateAction
1PR with unresolved [pj-review] threadspj-address-review
2PR, not a draft, with new commits after the last review, or with no reviewpj-review
3needs-input with a human answer after the last grillpj-grill-for-specs-readiness
4spec-ready, no open PR, no stop commentpj-implement, pj-repro for a bug, pj-decompose if implement said too big
5Freshpj-grill-for-specs-readiness, or pj-mock-it-up first for a UI change

Finish work before you start new work. In each priority, older items go first. Skip an issue with an open Depends on #x.

Human actions

List these apart. They have no command.

  • needs-input with no answer: answer the questions.
  • PR with a clean review, or at the round limit: approve and merge.
  • Parent issue with all children closed: close it.
  • An issue where a skill stopped with a comment: read it and decide.

Parallel

  • Actions can run in parallel if they work on different issues and PRs, and are not likely to change the same files.
  • Use the spec and the design to guess the files. If two actions can change the same files, put them in different groups.
  • Group A runs first. Group B runs after A, and so on.
  • Run each parallel action in its own session. Each skill uses its own worktree.
