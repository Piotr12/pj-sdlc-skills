Issue states

There are two labels. GitHub supplies the other states.

StateHow to know
FreshNo label. No linked PR.
needs-inputLabel. Only grill sets it. Grill asked questions, and a human must answer them.
spec-readyLabel. The issue meets the Definition of Ready.
ImplementedA PR links the issue.
DoneThe issue is closed.

An issue can have only one of the two labels. A skill that sets one label also removes the other.

Skill relations

SkillRule
pj-grill-for-specs-readinessIf the issue is a UI change and has no mockup, ask for one and suggest pj-mock-it-up. The issue is not spec-ready without a mockup. If the human defers, the agent runs pj-mock-it-up.
pj-implementBefore work starts, assess the size of the bite. If it is too big, recommend pj-decompose and stop.
The user can override this. The issue then goes through as one implementation run.
pj-decomposeCreate child issues under the parent issue. Each child links the parent, so the agent that implements it sees the full spec.
Children start as spec-ready.

Worktrees

Skills never work in the main checkout. Each skill run uses its own worktree, so parallel sessions are safe.

WorktreeUsed byLifetime
.worktrees/<n> on pj/<n>-<slug>pj-repro, pj-implement, pj-address-reviewUntil the PR is merged or closed
.worktrees/pr-<n> on the PR branchpj-address-review on a PR with no issueUntil the PR is merged or closed
.worktrees/review-<pr>, detached at the PR headpj-reviewOne run
.worktrees/att-<id>, detached at attachmentsEach skill that writes to attachmentsOne run
.worktrees/attachments on attachmentsThe human, to read filesPermanent
  • .worktrees/ is in .gitignore.
  • If the worktree exists, continue in it. If not, create it and install the dependencies.
  • Write to attachments from a detached worktree. Push with git push origin HEAD:attachments.
  • pj-healthcheck reports worktrees of merged or closed PRs.

Devlog

Agents write short notes for the human operator to devlog/ on the attachments branch. Agents do not read it.

  • One file for each day: devlog/yyyy-mm-dd-devlog.html. The date is in Europe/Warsaw time.
  • Each skill run appends one entry at the end of the file. If the file does not exist, create it with the page header first.
  • Each entry has a timestamp in Europe/Warsaw time, the skill, the target, the outcome, and a few short notes with links.
  • All skills write to it, except pj-next-round.
  • Parallel sessions append to the same file. The union merge driver joins the entries when a push needs a rebase.
  • To read it: git -C .worktrees/attachments pull, then open the file in a browser.
